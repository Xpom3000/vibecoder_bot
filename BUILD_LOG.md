## 2026-09-20 (2026-09-18 — 2026-09-20 по логам) — Базовый каркас, FAQ, guardrails, память

### Что сделано

**1. Каркас проекта**
- Структура: `bot.py`, `config.py`, `handlers/`, `keyboards/`, `services/`, `data/` — по паспорту бота.
- `/start` (с параметром `?start=landing` и без) + главное меню.

**2. Сценарии из паспорта**
- Раздел «Проекты» — три карточки-кейса (задача/стек/особенности/результат/ссылка).
- Раздел «Услуги» — список направлений с описаниями.
- Раздел «Этапы работы» — пять шагов процесса (справочный showcase, без привязки к конкретной заявке — для реального трекинга прогресса нужна была бы связка с БД и статусами заявок, это не делали).
- Форма брифа — FSM в четыре шага (имя → тип проекта → задача → контакт), с кнопкой отмены на каждом шаге.

**3. Хранилище заявок**
- Изначально: локальный файл `data/leads.jsonl`.
- Решение: лендинг оказался статическим HTML/CSS/JS без бэкенда — «общей БД с лендингом», как просил паспорт, физически не с чем делить.
- Перешли на SQLite (`services/db.py`, `data/vibecoder_bot.db`, таблица `leads`) — отдельная, но настоящая БД бота. Если у лендинга позже появится сервер — схему легко перенести.

**4. ИИ для свободных вопросов**
- Подключили DeepSeek (`services/ai.py`), знания — из `data/portfolio.py` (проекты, услуги, этапы) в системном промпте.
- Столкнулись с устаревшей моделью: `deepseek-chat` выведена из обращения 24.07.2026 → перешли на `deepseek-v4-flash`.
- По просьбе владельца временно переключали на Kimi (Moonshot AI, `kimi-k2.6`) — затем вернулись обратно на DeepSeek.
- Наполнили базу знаний реальными данными: цены и сроки по 4 услугам, новая услуга «Телеграм-бот», кейс «бот для доставки еды» (+20% к чеку), контакты (Telegram, email). После этого бот стал сам отвечать на вопросы о стоимости вместо пересылки владельцу.
- Явно прописали роль/тон в промпте: деловой вежливый консультант, только на основе базы знаний, честно признавать отсутствие ответа вместо выдумывания.

**5. Guardrails**
- Разделили исходы ответа ИИ на три типа: `answer` (обычный ответ), `unsure` (по теме, но нет в базе → пересылка владельцу), `offtopic` (не по теме или попытка обхода инструкций → вежливый отказ, владельца не беспокоим).
- Добавили инструкцию в промпт против промпт-инъекций (просьбы забыть инструкции, показать системный промпт, сменить роль).
- Добавили вторую линию защиты — keyword-фильтр (`services/guardrails.py`, ~25 regex-паттернов), отсекающий подозрительные сообщения ещё до обращения к DeepSeek. Проверили на 13 тестах (7 опасных фраз, 6 обычных вопросов) — ложных срабатываний нет.

**6. Память диалога**
- `services/history.py` — до 20 последних сообщений на пользователя (deque с автовытеснением старых), в памяти процесса (не в БД — обнуляется при перезапуске бота).
- В историю попадают только реальные пары вопрос-ответ; отказы и пересланные вопросы туда не пишутся.
- `/start` сбрасывает историю — новый разговор начинается с чистого листа.

**7. Прочее**
- Кнопка «Поддержка» — уведомление владельцу (имя, username, id) + контакты пользователю.
- Аватар бота — векторная молния в фирменном оранжевом с подписью «VibeCoder».
- Отдельный файл `data/knowledge-base.md` — справочный документ с ценами/сроками/кейсом/контактами вне кода бота.

### Проблемы и их причины

| Проблема | Причина | Решение |
|---|---|---|
| Бот не подключался к Telegram | Блокировка Telegram-серверов в РФ | Подключение через VPN-приложение владельца |
| `pip`/`python` не распознаются в PowerShell | Не активировано окружение / Windows Store alias вместо реального Python | `.\.venv\Scripts\Activate.ps1`, позже `python -m pip ...` |
| DeepSeek не отвечал | Модель `deepseek-chat` устарела 24.07.2026 | Смена на `deepseek-v4-flash` |
| Бот полностью замолкал на свободных вопросах | Сбой отправки уведомления админу (`send_message`) не был обёрнут в try/except и обрывал весь хендлер | `services/notify.py` — безопасная отправка с логированием ошибок |
| «Заявок нет в БД» | На момент проверки не были обновлены локальные файлы / не переустановлены зависимости после правок | Пересборка архива, `pip install -r requirements.txt`, проверка через `sqlite3` напрямую |
| DeepSeek отвечал `402 Insufficient Balance` | Не было средств на аккаунте DeepSeek | Не блокирующая проблема кода — подтверждено, что fallback-пересылка владельцу сработала корректно |

### Осознанные допущения (требуют внимания владельца)
- Тексты по трём кейсам (`ovenmeal.com`, `homey.com`, `nexta.io`) — черновик со слов другого ИИ, **не проверены на соответствие реальности**, нужна вычитка перед показом клиентам.
- БД — отдельная (SQLite), не «общая с лендингом», как буквально написано в паспорте, из-за отсутствия бэкенда у лендинга.
- Guardrails на базе keyword-фильтра и промпт-инструкций — это не 100%-непробиваемая защита, а разумный практический барьер.

### Не сделано (бэклог)
- Онлайн-оплата.
- Деплой на сервер для круглосуточной работы (сейчас бот живёт, пока запущен `python bot.py` на компьютере владельца).
- Реальный трекинг «пользователь на каком шаге сейчас» в разделе «Этапы работы».

# CLAUDE.md

Контекст проекта для Claude Code. Файл описывает, что за продукт мы делаем, из чего он состоит и каких правил держаться при генерации кода.

## Проект

**VibeCoder Assistant** — Telegram-бот-консультант по портфолио VibeCoder.

Бот показывает проекты из лендинга, рассказывает об услугах, проводит по этапам работы и собирает заявку на бриф. Работает как продолжение лендинга: пользователь жмёт кнопку «Написать в Telegram» и попадает в бота уже в контексте.

**Задачи:**
- Отвечать мгновенно и круглосуточно.
- Не терять входящие заявки.
- Освободить владельца от ответов на однотипные вопросы.

## Целевая аудитория

- Заказчики, которым нужен лендинг, многостраничный сайт или промо-страница.
- Те, кто увидел лендинг VibeCoder и хочет быстро посмотреть кейсы в Telegram, не открывая сайт.

## Стек и интеграции

| Компонент | Назначение |
|---|---|
| Telegram Bot API | работа бота в Telegram |
| Python + aiogram | логика бота |
| DeepSeek | обработка свободных вопросов пользователя |
| База знаний | ответы на основе портфолио |
| БД | хранение заявок (общая с лендингом) |
| Сервер | круглосуточная работа после публикации |
| Claude Code | генерация кода |

## Функции для пользователя

1. **Каталог проектов** — три кейса с лендинга: `ovenmeal.com`, `homey.com`, `nexta.io`. Каждый с описанием задачи, стека и результата.
2. **Раздел услуг** — лендинг, многостраничный сайт, промо-страница, интеграция форм. Краткое описание + кнопка «Заказать».
3. **Этапы работы** — пять шагов: бриф → прототип → дизайн → сборка → передача. Бот показывает прогресс по проекту.

## Функции для владельца

1. **Форма заявки на бриф** — имя, тип проекта, описание задачи, контакты. Сохраняется в БД, админу приходит уведомление.
2. **Ответы на частые вопросы** — сроки, стоимость, стек, адаптивность.

## Сценарии использования

### Сценарий 1. Переход с лендинга
1. Кнопка «Написать в Telegram» ведёт на `t.me/vibecoder_bot?start=landing`.
2. Бот видит параметр `start=landing` и отвечает: «Привет! Ты с лендинга VibeCoder. Могу показать проекты, рассказать про услуги или сразу записать на бриф. Что интересует?»
3. Пользователь выбирает кнопку → бот ведёт по сценарию.

### Сценарий 2. Просмотр проектов
1. Пользователь жмёт «Проекты» → видит три карточки:
   - `ovenmeal.com` — лендинг доставки здорового питания
   - `homey.com` — многостраничный сайт агентства недвижимости
   - `nexta.io` — промо-страница IT-продукта
2. По нажатию на карточку: задача, стек, особенности, результат, ссылка «Смотреть проект».
3. В конце — кнопка «Хочу такой же» → переход к форме брифа.

### Сценарий 3. Выбор услуги
1. Пользователь жмёт «Услуги» → видит четыре варианта: лендинг, многостраничный сайт, промо-страница, интеграция форм.
2. Выбирает нужное → бот даёт краткое описание + кнопку «Заказать» → форма брифа.

### Сценарий 4. Заявка на бриф
1. Бот спрашивает по шагам: имя → тип проекта (выбор из кнопок) → описание задачи → телефон/email.
2. Данные сохраняются в БД (общей с лендингом).
3. Админу приходит карточка:

```text
Новая заявка на бриф
Имя: Анна
Тип: Лендинг
Задача: Лендинг для фитнес-студии
Контакт: @anna / +7999...
Источник: landing
```

## Ограничения

- Только текст. Аудио и изображения пока не распознаются.
- Бот не выдумывает ответы: если ИИ не уверен — пересылает вопрос владельцу.
- Онлайн-оплаты на данном этапе нет, появится позже.

## Риски

- ИИ может галлюцинировать и давать неточные ответы → нужны проверки и фолбэк на владельца.
- Токен бота может утечь при случайной публикации → токен и ключи только в переменных окружения, никогда в коде и коммитах.

## Правила для работы над кодом

- Язык интерфейса бота — русский, обращение на «ты» (как в приветствии со сценария 1).
- Секреты (`BOT_TOKEN`, ключ DeepSeek, доступ к БД) — только через `.env` / переменные окружения. `.env` в `.gitignore`.
- Асинхронный код: aiogram 3.x, `async/await`, без блокирующих вызовов в хендлерах.
- Ответы модели ограничены базой знаний по портфолио. Нет уверенного ответа — не придумывать, а предложить переслать вопрос владельцу.
- Заявки пишутся в ту же БД, что и заявки с лендинга — схему согласовывать с лендингом, а не дублировать.
